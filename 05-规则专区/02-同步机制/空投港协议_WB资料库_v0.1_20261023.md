## 一、定位

| 层 | 载体 | 职责 |
|---|---|---|
| 正本层 | `~/我的知识库/`（vault）+ Gitee/GitHub 双库 | 唯一正本，git 管道管理（**主投递通道**） |
| **空投港** | **WorkBuddy 资料库 · 我的文档** | **备用通道1**（v0.2 定位）：主通道不可达时（手机派活/vault远端场景）投单据用——施工单/返修包/协议副本/经验卡 |
| **备用通道2** | **豆包云盘**（10GB，v0.3 注册） | **媒体线投递层**：图片·多媒体产出的视频解析稿/设计稿/素材副本。**投递细则**（《豆包内置云盘使用说明》2026-10 实测版）：①AI不能主动扫盘，投递=对话+号→云盘文件→手动勾选；②**云电脑模式增强：Agent 生成文件后直接说"把XX上传到云盘"即落盘**（返回 my.feishu.cn/file 链接，绕过手机端不能下载的坑）；③手机对话附件不入云盘需手动传；④分享=登录墙已实测（不支持匿名公开）；⑤**本地电脑模式 Agent 可直改/直删云盘文件**（10-23 14:00 实测）——规则更新一句话搞定、过期副本一句话清理；删副本不伤正本（正本 vault 兜底）。规则照搬三件套：只放副本/不放凭证/命名带日期 |
| 展示层（二期观察） | workbuddy.link 轻应用 | 免登录对外展示，默认关闭不启用 |

**铁律**：空投港只放**单据副本**，永不放正本；WB 干活的成果仍落 vault 走 git 管道。
**存放决策（10-23 补）**：常备**操作手册/规则类**文件（如豆包云盘说明）只存 vault 正本层（04-产出副本/），不存资料库——不是单据不走空投港；WB 需要时派单话术指路即可。防双主版本漂移。

## 二、怎么投（佛爷操作，10秒）

1. X线交付 MD 文件 → 你手机上（或电脑端）**存入资料库·我的文档**
2. 命名规范：`{单据名}_YYYYMMDD.md`（如 `看板返修包_20261023.md`），同日改版加 `_v2`
3. 旧单据：不删，靠命名日期认新；同名覆盖前确认 WB 已回执

**链接形态权限（v0.2 实测补充）**：

## 三、WB 怎么取（派单话术模板）

```
读资料库《{单据名}_YYYYMMDD.md》（引用时勾选"最新版本"），按单施工。
回执格式：逐条 修复/未修+原因；完成后把成果落 ~/我的知识库/ 走 git。
```

- WB 取数方式：资料库中选中该文档 →「···」→**添加到任务**（整篇进上下文，不用粘贴）
- 手机端也能派活：资料库在任意设备登录可见，你在手机上直接对 WB 会话发上面的话术

## 四、版本纪律

- 引用必勾"**引用最新文档版本**"（WB 侧），防旧单返工
- 单据内容大改 = 出新文件（加日期/版本后缀），不静默覆盖
- X线台账同步记："投递=资料库+文件名"，回执以 WB"已读单"为准

## 五、安全红线

- 🚫 资料库**不放**：token/密钥/密码、未脱敏内部数字、他人隐私数据
- 🚫 "发布为网站"（workbuddy.link 公开链接）**默认不开**；确需对外分享先过脱敏规则（对外演示隐内部数字），开前报 X线
- 团队空间暂不用（单人不涉及多人协作；将来有协作需求再评估权限档位：查/编/管）
